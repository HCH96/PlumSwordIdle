# 사양 문서 양식

`docs/spec/<기능>.md` 를 이 양식으로 쓴다. 절 제목(`## 목표` 등) 아홉 개는 글자와 순서를 바꾸지 않는다. `make-tasks` 스킬과 루프 에이전트가 이 제목으로 절을 찾는다. 해당 없는 절도 지우지 말고 "해당 없음"과 이유 한 줄을 적는다.

## 쓰는 법

- **목표**: 이 기능이 게임에서 무엇을 하는지 두세 줄. `docs/plan.md` 2장의 어느 항목인지.
- **동작**: 무엇이 언제 어떻게 바뀌는지 항목으로. 경계 상황은 표로 (경우 / 결과 / 값의 변화).
- **수치**: 공식은 식으로, 값은 숫자로. 숫자 타입과 반올림. 임시값은 "(임시)".
- **연결 지점**: C# 모양 그대로. "제공하는 것"과 "필요한 것"으로 나눈다. 메서드마다 경계 상황 동작 한 줄.
- **화면**: 보여 주는 것, 누르는 것, 누를 수 없을 때. 위치는 "화면 위쪽 전투 / 아래쪽 강화 UI" 기준으로 말로.
- **저장**: 저장할 값(이름, 타입), 처음 시작 값, 오프라인 보상과의 관계.
- **범위 밖**: 이번에 하지 않는 것과, 하게 되면 어느 기능이 할지.
- **완료 조건 초안**: 테스트 하나로 옮길 수 있는 문장. "무엇을 주면(상황) 무엇이 나온다(기대 결과)" + 숫자. 경계 상황 표의 줄마다 하나 이상. `make-tasks` 가 이것을 작업별로 나눠 옮긴다.
- **결정 기록**: 이 대화에서 물은 것과 답. 답한 방식(사용자 선택 / 추천 수락 / 임시값)도 적는다.
