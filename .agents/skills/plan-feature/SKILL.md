description: 만들고 싶은 기능을 대화로 구체화해서 "루프가 더 물어볼 것이 없는" 사양 문서(docs/spec/<기능>.md)로 정리한다. 이미 정해진 것은 공용 문서에서 찾아 다시 묻지 않고, 동작·경계 상황·수치·연결 지점·화면·저장·범위 밖을 한 주제씩 선택지와 추천안으로 묻고, 승인을 받은 뒤 사양 문서를 쓰고 docs/spec/index.md 에 한 줄 추가한다. 게임 기획 원본(docs/design/)에서 해당 기능의 절만 골라 읽는다. 사용자가 "이런 기능 만들고 싶어", "기획하자", "사양 정리해 줘", "○○ 기능 설계해 줘"라고 하거나, make-tasks 를 쓰려는데 사양이 아직 없을 때 쓴다. 작업 문서는 만들지 않는다 (그건 make-tasks).
---

이 프로젝트의 공통 스킬 원본을 사용한다.

1. `docs/index.md`에서 시작해 `docs/dev/workflow.md`의 공통 실행 기준을 읽는다.
2. 이 파일이 있는 폴더에서 `../../..`가 저장소 루트다. 그 루트의 `.claude/skills/plan-feature/SKILL.md`를 읽고 해당 절차를 따른다. 이 진입점만 읽고 작업하지 않는다.
3. 원본의 명령·저장소 경로는 원본 프로젝트 루트 기준이고, 마크다운 상대 링크는 원본 문서 위치 기준이다. linked worktree에서 시작했다면 공통 실행 기준에 따라 원본 checkout을 먼저 확인한다. 로컬 상태판은 원본 프로젝트 하나만 쓴다.
4. 원본에 적힌 Read·AskUserQuestion 등의 도구 이름은 현재 환경의 파일 읽기·질문 기능으로 대응한다. 질문 기능이 없으면 일반 대화로 묻고, 필요한 답변이 올 때까지 해당 작업은 진행하지 않는다.
5. 본문·템플릿·보조 프로그램을 복제하지 않는다. 기존 사용자 승인과 원본 절차의 쓰기 범위를 지킨다. 원본 파일이 없으면 진행하지 말고 누락 경로를 알린다.
