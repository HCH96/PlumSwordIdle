description: 자동 개발 루프가 통합 브랜치(integration)에 합쳐 둔 루프들을 main 에 올리기 전에 확인한다. 루프마다 남은 증거(docs/evidence 의 보고서, 화면 갈무리, 리뷰어의 완료 조건별 테스트 표)를 먼저 읽고, 그것이 실제 코드와 맞는지 확인한다. 작업마다 보고서와 실제 변경, 완료 조건별 테스트, 보고서의 "가정"(사람이 몰랐던 결정), "하지 말 것" 침범을 살피고, 구조 규칙 위반(Core 의 유니티 의존, 씬·프리팹·설정 변경, .meta 누락, 루프 자체 변경, 약해진 테스트)을 다시 찾아 "올려도 됨 / 올리고 후속 작업으로 고침 / 올리지 않음"으로 결론을 낸 뒤 올리는 명령과 되돌리는 명령을 보여 준다. 사용자가 "루프 리뷰해 줘", "루프 끝났대, 확인해 줘", "올려도 돼?", "합쳐도 돼?", "증거 봐 줘", "통합 브랜치 봐 줘", "디스코드에 모든 작업 끝 알림 왔어"라고 할 때 쓴다. 코드는 고치지 않고, 사용자가 분명히 시킬 때만 main 에 올린다. 푸시는 하지 않는다.
---

이 프로젝트의 공통 스킬 원본을 사용한다.

1. `docs/index.md`에서 시작해 `docs/dev/workflow.md`의 공통 실행 기준을 읽는다.
2. 이 파일이 있는 폴더에서 `../../..`가 저장소 루트다. 그 루트의 `.claude/skills/review-loop/SKILL.md`를 읽고 해당 절차를 따른다. 이 진입점만 읽고 작업하지 않는다.
3. 원본의 명령·저장소 경로는 원본 프로젝트 루트 기준이고, 마크다운 상대 링크는 원본 문서 위치 기준이다. linked worktree에서 시작했다면 공통 실행 기준에 따라 원본 checkout을 먼저 확인한다. 로컬 상태판은 원본 프로젝트 하나만 쓴다.
4. 원본에 적힌 Read·AskUserQuestion 등의 도구 이름은 현재 환경의 파일 읽기·질문 기능으로 대응한다. 질문 기능이 없으면 일반 대화로 묻고, 필요한 답변이 올 때까지 해당 작업은 진행하지 않는다.
5. 본문·템플릿·보조 프로그램을 복제하지 않는다. 기존 사용자 승인과 원본 절차의 쓰기 범위를 지킨다. 원본 파일이 없으면 진행하지 말고 누락 경로를 알린다.
