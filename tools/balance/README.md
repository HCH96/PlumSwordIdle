# 밸런스 시뮬레이터

유니티 없이 `Assets/Scripts/Core/` 소스를 그대로 컴파일해, 게임(`GameRoot`)과 같은 조립으로 플레이를 돌린다. 수치 표(`BalanceTable`, `docs/spec/balance.md`)를 JSON 으로 바꿔 넣고, 결과를 그래프 보고서로 본다.

- 자동 강화를 켜고, 회귀 규칙을 켠 채 1-1부터 시작한다 (새 게임).
- 1/60초 프레임마다 `Battle.Tick` → `StageProgress.Tick` 순서로 부른다 (`CombatView`, `StageView` 와 같다). 화면이 끼워 넣는 쓰러짐 연출 대기도 흉내 낸다.
- 사람의 손 강화, 오프라인 보상, 시작 화면은 없다. 실제 플레이 감각(속도감)은 에디터에서 따로 본다.
- 루프 작업이 아니다. 루프의 관문은 `tools/` 변경을 막으므로, 이 폴더는 사람이 대화에서 고친다.

## 쓰는 법 (프로젝트 폴더에서)

```
dotnet run --project tools/balance -- --config tools/balance/configs/내설정.json
```

- `--config` 를 여러 번 주면 설정끼리 겹쳐 비교한다. 없으면 기본 표 하나.
- `--seeds 5` 난수 시드 수, `--minutes 40` 최대 게임 시간, `--out <폴더>` 결과 폴더 (기본 `tools/balance/out/<날짜-시간>`).
- `--dump-default <파일>` 기본 표를 설명과 함께 JSON 으로 쓴다. 새 설정은 `configs/default.json` 을 복사해 바꾸면 된다.
- 결과: `report.html` (그래프), `data.json`, seed 마다 1초 간격 CSV. `out/` 은 깃에서 제외된다.
- 보고서는 그래프 라이브러리(Chart.js)를 cdnjs 에서 받으므로 인터넷이 필요하다.

## 설정 JSON

바꾸고 싶은 값만 적는다. 적지 않은 값은 기본 표 그대로다. `_` 로 시작하는 칸은 설명이라 무시한다.

```json
{
  "FinalBossHealth": 3000,
  "NormalHealth": [30, 10, 1.08],
  "SubstageStep": 0.142857
}
```

- 곡선은 `[base, linear, growth]`. 값 = 내림((base + linear × n) × growth^n).
- 몬스터·보상의 n = (스테이지 − 1) + `SubstageStep` × (구간 − 1). 강화 비용의 n 은 지금 단계.
- 허용 범위를 벗어나면 `Validate()` 오류로 멈춘다.

## 보고서에서 보는 것

- **요약 카드**: 천마 첫 처치 시각(중앙값·범위), 평균 회귀 수. 목표(약 20분, 회귀 3회)에 가까우면 초록.
- **진행도**: 시간별 스테이지-구간. 회귀(✕), 천마 처치(★), 경지 돌파(▲).
- **전투 여유**: 상대 하나를 쓰러뜨리는 공격 수와 제자가 버티는 공격 수. 실선이 점선 위로 올라가는 곳이 막히는 곳이다.
- **금화, 강화 단계, 능력치 vs 상대, 경지**.
- **처음 완료 시각 표**, **시도 표**(고른 seed의 큰 스테이지 시도별 걸린 시간), **수치 표**(설정끼리 다른 값 굵게).

## 정한 수치를 게임에 넣기

시뮬레이터는 게임의 기본 표를 바꾸지 않는다. 정한 값은 `make-tasks` 로 `BalanceTable.Default` 를 바꾸는 작업 문서를 만들어 루프에 넣는다. 그때 지금 수치를 가정한 기존 테스트의 기대값이 바뀐다.
