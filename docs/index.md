# 문서 색인

작업을 시작하기 전에 이 색인을 읽고, 필요한 폴더의 색인으로 가서 필요한 문서의 필요한 절만 읽는다. 폴더마다 `index.md`가 있다.

| 찾는 것 | 가는 곳 | 누가 읽는가 |
| --- | --- | --- |
| 구현할 기능의 규칙, 수치, 연결 지점 | [spec/index.md](spec/index.md) | 구현하는 에이전트, 스킬 |
| 코드 구조, 루프 사용법, 작업 문서 양식 | [dev/index.md](dev/index.md) | 구현하는 에이전트, 스킬 |
| 게임 기획 원본 | [design/index.md](design/index.md) | 사람, 기획 스킬(`plan-feature`) |
| 프로젝트 계획서 | `project/` | 사람 |
| 옛 문서 보관 | `archive/` | 사람 |
| 완료된 작업 문서 기록 | `history/` | 루프 스크립트가 추가. 리뷰 때 본다 |

## 사람용 문서는 읽지 않는다

- `design/`, `project/`, `archive/`는 사람이 쓰고 읽는 문서다. **작업 문서를 구현하는 에이전트는 이 세 폴더를 읽지 않는다.** 구현에 필요한 내용은 사양(`spec/`)과 작업 문서에 이미 옮겨져 있다.
- 사양과 작업 문서에 없는 내용이 필요하면 기획 문서를 찾아 읽지 말고, 규칙의 "애매한 점 처리"대로 가정으로 정하거나 보류로 보고한다.
- 예외는 기획 스킬(`plan-feature`)뿐이다. 사양을 만들 때 `design/index.md`가 가리키는 절을 읽는다. `project/`와 `archive/`는 어떤 에이전트도 작업에 쓰지 않는다.

새 문서를 만들거나 문서의 역할이 바뀌면 그 폴더의 색인을 고친다. 이 최상위 색인은 폴더가 늘 때만 고친다.
