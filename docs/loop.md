# AI 자동 개발 루프 (1차 버전)

`tasks/todo/`의 작업 문서를 하나씩 꺼내 클로드 코드 CLI(헤드리스)로 계획·구현하고, 테스트를 통과하면 커밋한다. 설계 배경은 [plan.md 4장](plan.md) 참고.

## 실행

```
python tools/loop/run_loop.py
```

- 필요할 때 켜고, `tasks/todo`가 비면 끝난다.
- 종료 코드: `0` 정상, `1` 오류로 멈춤, `2` 사용량 한도로 멈춤, `3` 시작 전 점검 실패.
- 준비물: 깃, 클로드 코드 CLI(로그인 완료), 파이썬 3.11 이상(외부 패키지 없음).

## 파일

| 경로 | 깃 추적 | 설명 |
| --- | --- | --- |
| `tools/loop/run_loop.py` | O | 루프 본체 |
| `tools/loop/loop_config.json` | O | 설정값 (아래 표) |
| `.env` | X | 디스코드 웹훅 URL. 키 이름은 `.env.example` 참고 |
| `tasks/` | X | 로컬 상태판. 브랜치와 상관없이 폴더 위치가 곧 작업 상태 |
| `.loop/state.json` | X | 진행 중인 루프 정보 |
| `.loop/result.json` | X | 클로드가 작업 결과를 스크립트에 넘기는 파일 (일시적) |
| `.loop/logs/` | X | 실행 로그, 클로드 출력 |
| `docs/history/` | O | 완료된 작업 문서 원본(보고서 포함). 완료된 작업만 들어간다 |

## 설정값 (`tools/loop/loop_config.json`)

| 키 | 기본값 | 설명 |
| --- | --- | --- |
| `base_branch` | `main` | 루프 브랜치를 따는 기준. 스크립트는 읽기만 한다 |
| `loop_branch_prefix` / `task_branch_prefix` | `loop/` / `task/` | 브랜치 이름 앞부분 |
| `max_retries` | `5` | 작업 하나당 클로드 실행 최대 횟수. 넘으면 보류 |
| `test_command` | `""` | 테스트 명령. 비어 있으면 건너뛰고 통과로 본다. 종료 코드 0이면 통과 |
| `test_timeout_min` | `30` | 테스트 시간 제한(분) |
| `claude_command` | `claude` | 클로드 코드 CLI 명령 |
| `claude_timeout_min` | `60` | 클로드 실행 1회 시간 제한(분). 넘으면 오류로 멈춤 |
| `claude_permission_mode` | `acceptEdits` | 헤드리스 실행 권한 모드 |
| `claude_allowed_tools` / `claude_disallowed_tools` | 설정 파일 참고 | 허용·금지 도구. 깃 상태 변경과 `.env` 접근은 금지 |

## 브랜치 구조

```
main                      스크립트는 체크아웃·커밋·병합·푸시하지 않는다
 └─ loop/<날짜-시간>        루프 브랜치. 루프의 작업이 모두 끝날 때까지 계속 쓴다
     ├─ task/<문서이름>     기능 브랜치. 완료되면 루프 브랜치에 fast-forward 병합
     └─ task/<문서이름>     보류되면 작업 중 상태를 커밋해 남겨둔다
```

- 푸시는 하지 않는다. 루프 브랜치를 main에 합치는 것은 사람이 확인하고 직접 한다.

### 진행 중인 루프와 완료된 루프

`.loop/state.json`의 `status`로 구분한다.

- `active`(진행 중): 다시 실행하면 새로 만들지 않고 이 루프 브랜치를 이어서 쓴다.
- `finished`(완료): todo와 blocked가 모두 비었을 때만 이 상태가 되고, DONE 채널로 "루프 종료" 알림(처리한 작업 목록, 루프 브랜치)을 보낸다.
- todo만 비고 보류가 남으면 루프는 `active`로 남고 스크립트만 끝난다(LOG 알림).
- 진행 중인 루프가 아닌 `loop/*` 브랜치가 main에 합쳐져 있지 않으면 "완료됐지만 안 합쳐진 루프"로 보고 시작하지 않는다. 상태 파일이 지워져도 안전한 쪽(멈춤)으로 판단된다.

## 흐름

1. **시작 전 점검**: 커밋 안 된 변경이 있거나, 완료됐지만 main에 안 합쳐진 루프 브랜치가 있으면 시작하지 않고 STOPPED 알림.
2. **루프 브랜치 준비**: 진행 중인 루프가 있으면 체크아웃, 없으면 main에서 `loop/<날짜-시간>` 생성.
3. **상태 맞추기**
   - doing에 남은 문서: 기능 브랜치에 기록(`docs/history/<이름>`) 커밋이 있으면 루프 브랜치에 합치고 done으로, 없으면 todo로 되돌린다.
   - done인데 루프 브랜치에 기록이 없는 문서: 기능 브랜치에 기록이 있으면 합치고, 없으면 blocked로 옮겨 확인을 요청한다.
4. **꺼내기**: todo에서 파일 이름 순서(`001_`, `002_` …)로 첫 문서를 doing으로 옮긴다. LOG "작업 시작".
5. **기능 브랜치**: `task/<문서이름>`을 루프 브랜치에서 만든다. 이미 있으면(보류됐던 작업) 루프 브랜치를 먼저 병합해 최신으로 맞춘다. 병합이 충돌하면 기존 기능 브랜치를 지우고 루프 브랜치에서 새로 만든다.
6. **클로드 실행**: 작업 문서를 처리하고 작업 문서에 `## 보고서`를 덧붙인 뒤 `.loop/result.json`을 쓴다.
7. **테스트**: 실패하거나 결과 파일이 없으면 같은 세션을 이어(`--resume`) 실패 내용을 넘기고 다시 실행한다. LOG "재시도 n회째".
8. **완료**: 작업 문서 원본을 `docs/history/`로 복사 → 기능 브랜치에 커밋 → 루프 브랜치에 fast-forward 병합 → 성공하면 done으로 이동. DONE 알림(요약, 브랜치).
9. **보류**: 클로드가 blocked를 보고하거나 재시도 한도를 넘으면 작업 중 상태를 기능 브랜치에 커밋하고, 문서에 `## 보류 사유`(사유·질문·추천안)를 적어 blocked로 옮긴다. BLOCKED 알림. 루프는 다음 작업으로 계속한다.
10. todo가 비면 끝(위 "진행 중인 루프와 완료된 루프" 참고).

## 결과 파일 형식 (`.loop/result.json`)

```json
{"status": "done", "summary": "바뀐 내용 요약"}
{"status": "blocked", "reason": "막힌 이유", "question": "질문", "recommendation": "추천안"}
```

## 멈춤

| 상황 | 처리 |
| --- | --- |
| 사용량 한도 | 작업 중 상태를 기능 브랜치에 커밋, 문서를 todo로 되돌림, 루프 브랜치는 그대로. STOPPED 알림 |
| 예상 못 한 오류·시간 초과 | 상태를 건드리지 않고 STOPPED 알림에 오류 요약만 보냄 |
| 시작 전 점검 실패 | 시작하지 않고 STOPPED 알림 |

## 디스코드 알림

`.env`의 키 4개로 채널을 나눈다. 값이 비어 있으면 그 채널은 건너뛴다. 전송 실패는 로그에만 남기고 루프는 계속한다.

| 키 | 보내는 내용 |
| --- | --- |
| `DISCORD_WEBHOOK_DONE` | 작업 완료(요약, 브랜치), 루프 종료(처리 목록, 루프 브랜치) |
| `DISCORD_WEBHOOK_BLOCKED` | 막힌 이유, 질문, 추천안 |
| `DISCORD_WEBHOOK_STOPPED` | 사용량 한도, 오류, 시작 전 점검 실패 |
| `DISCORD_WEBHOOK_LOG` | 루프 시작, 작업 시작, 재시도 몇 번째, 기능 브랜치 새로 시작, 보류만 남은 종료 |

## 루프 확인 후 정리

루프 종료 알림을 받으면 루프 브랜치를 확인하고 직접 처리한다.

- main에 합치기: `git checkout main` 후 `git merge loop/<날짜-시간>`. 합치고 나면 다음 실행은 새 루프를 만든다.
- 합치지 않고 버리기: `git branch -D loop/<날짜-시간>`과 그 루프의 `task/*` 브랜치를 지우고, `.loop/state.json`을 지우고, 필요하면 `tasks/done`과 `docs/history`의 해당 문서를 정리한다.

## 2차 버전으로 미룬 것

코덱스 전환, 선행 작업 판단, 묶음 단위 처리, 계속 켜두는 감시 모드. 그 전까지 todo 문서는 이름 앞 번호 순서로 처리한다.
