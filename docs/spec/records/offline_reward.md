# 오프라인 보상 기록

[offline_reward.md](../offline_reward.md) 사양의 이력이다. 구현에 필요한 규칙은 사양 문서에 모두 있으므로 **구현하는 에이전트는 읽지 않아도 된다.** 기획 스킬(`plan-feature`)이 이미 정한 것을 다시 묻지 않으려고 읽는다.

## 결정 기록

| 질문 | 답 | 방식 |
| --- | --- | --- |
| 백그라운드 복귀를 어떻게 처리하는가 | 10초 이상이면 `[Game]` 루트를 다시 만들어 저장 파일로 켤 때와 같이 시작한다. 다른 사양은 고치지 않는다 | 추천 수락, 2026-11-17 |
| 시작 화면이 생기기 전 보상 창의 시점 | 불러오기 직후(`Begin` 자리). 시작 화면이 생기면 `이어하기` 뒤로 옮기도록 연결 지점에 적는다 | 추천 수락, 2026-11-17 |
| 시작 화면에 머문 시간을 빼는 법 | 켤 때 한 번 계산해 두고, 받기 전에는 `AutoSave`를 꺼 둔다. 누를 때 다시 계산하지 않는다 | 추천 수락, 2026-11-17 |
| 받기의 순서 | `Wallet.Add` → `AutoSave.Enable()` → `SaveNow(now)`. 금화와 시각이 파일 하나에 함께 쓰인다 | 추천 수락, 2026-11-17 |
| 받기 뒤 저장 실패 | 창에 남아 `RETRY`만. 금화는 다시 주지 않고 성공해야 전투 시작 | 추천 수락, 2026-11-17 |
| 받기 전에 끄면 | 아무것도 쓰지 않는다. 다음에 옛 저장 시각부터 다시 계산 (창을 띄워 둔 시간 포함, 8시간 상한) | 추천 수락, 2026-11-17 |
| 백그라운드 10초 미만 복귀 | 다시 만들지 않고 그대로 계속 | 추천 수락, 2026-11-17 |
| 보상 기준 시각을 따로 저장하는가 | 하지 않는다. 저장 사양의 `savedAtUtcTicks`를 쓴다 (판 1 그대로) | 위 결정에서 따라 나옴 |
| 음수 시각 | 경과 0, 예외 없음 | 직접 정함 |
| 정확히 8시간 | 상한 아님 (`>`로 판정) | 직접 정함 (기획의 "초과하면") |
| 복귀 시 저장이 최신인지 | `!HasFailed && !IsDirty`. 아니면 다시 만들지 않음 | 직접 정함 |
| 다시 만드는 방법 | 루트를 끄고 지운 뒤 다음 프레임에 `GameRestarter`가 새로 만든다 | 직접 정함 (같은 프레임이면 지워질 EventSystem을 다시 씀) |
| 배치 모드의 복귀 | 감시를 만들지 않는다 | 직접 정함 (메모리 저장소라 다시 만들면 진행이 사라짐) |
| 창이 열린 동안 강화 멈춤 | 가림막이 입력을 막는다 | 직접 정함 |
| 시간 표시 | `H:MM:SS` 영문 | 직접 정함 |
