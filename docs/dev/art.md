# 픽셀아트 에셋 기준

스프라이트와 화면 코드의 크기·가져오기 기준이다. 새 에셋의 그림체와 제작 순서는 [제자 기준 아트 스타일](art_style.md)을 따른다. 아래 에셋별 크기는 게임 적용을 위한 기존 계획값이며, 제자 SD 원본과의 차이는 적용 전에 결정한다.

## 기본 숫자

| 항목 | 값 | 비고 |
| --- | --- | --- |
| 화면 방향 | 가로 | |
| 기준 해상도 | **640×360** | 3배 = 1920×1080, 4배 = 2560×1440. 항상 정수배로 확대한다 |
| PPU (Pixels Per Unit) | **32** | 모든 스프라이트에 같은 값을 쓴다. 에셋마다 다르게 두지 않는다 |
| 카메라 | Orthographic, 크기 5.625 | 360 ÷ 2 ÷ 32. 화면 높이가 11.25 유닛이다 |
| 안전 영역 | 가운데 640×360 | 캐릭터 위치, 전투, UI 같은 중요한 요소는 이 안에 둔다 |

- 카메라에는 URP의 Pixel Perfect Camera(기준 해상도 640×360, PPU 32)를 붙여 픽셀이 정수배로만 보이게 한다. 화면은 코드로 조립하므로(`architecture.md`의 "화면: 코드로 조립한다") 이 설정도 코드에서 한다. 2026-11-17부터 `CombatView`가 붙인다 (Grid Snapping = Pixel Snapping, Crop Frame = None). 그래서 `PlumSword.Game` 어셈블리가 `Unity.RenderPipelines.Universal.2D.Runtime`을 참조한다.
- UI의 `CanvasScaler`는 기준 해상도 640×360, Scale With Screen Size, 높이에 맞춤(Match = 1)으로 둔다. UI 스프라이트도 같은 픽셀 크기 기준으로 그린다.

## 화면 비율

폰은 16:9보다 가로로 긴 경우가 많다. 높이 360을 고정하고 폭이 늘어난다.

| 비율 | 폭 |
| --- | --- |
| 16:9 | 640 |
| 19.5:9 | 780 |
| 20:9 | 800 |

- 늘어난 양옆에는 배경만 보이게 한다. 중요한 요소는 가운데 640 안에 둔다.
- UI는 화면 가장자리에 앵커로 붙이고, 노치가 있는 기기를 위해 `Screen.safeArea` 안에 배치한다.

## 에셋별 캔버스 크기

| 종류 | 캔버스 (px) | 비고 |
| --- | --- | --- |
| 주인공 | 48×48 (계획) | 몸은 키 32px 정도, 남는 칸은 검 휘두르는 동작 여유분. 더 크게 보이려면 64×64. **실제 적용(2026-11-17)은 PixelLab 원본 76×76·76×80 칸, 몸 키 약 53px** ([assets.md](assets.md) "캐릭터") |
| 일반 몬스터 | 48×48 | 사람형이라 주인공과 같은 캔버스·같은 키로 그린다 |
| 보스 | 96×96 ~ 128×128 | 화면 높이의 1/3 정도 |
| 검기·매화 이펙트 | 64×64 ~ 96×96 | |
| 아이콘 (재화, 강화 항목 등) | 16×16 또는 32×32 | UI에서 2배, 3배 같은 정수배로 확대 |
| UI 패널·버튼 | 작게 그리고 9-slice로 늘림 | 예: 24×24 테두리 |
| 배경 | 높이 360, 폭 800 이상 | 또는 가로로 이어 붙여 반복되는 타일형. 시차 스크롤용이면 레이어(먼 산, 중간, 가까운 땅)로 나눈다 |

실행해 보고 전체가 작거나 크면 에셋을 하나씩 키우지 않고 기준 해상도를 바꾼다 (예: 480×270으로 낮추면 모두 1.33배 커 보인다). 특정 종류만 키워야 하면 그 에셋을 새 캔버스 크기로 다시 그린다. 한 에셋만 배율로 키우면 그 에셋만 픽셀 크기가 달라져 다른 에셋과 섞였을 때 어색하다.

에셋이 아직 없을 때 쓰는 대체 표시(단색 사각형 등)도 위 크기에 맞춰 만든다. 예: 주인공 대체 표시는 48×48px = 1.5×1.5 유닛.

## 그리는 규칙

- 같은 애니메이션의 프레임은 캔버스 크기와 피벗을 모두 같게 한다. 시트로 묶을 때는 한 칸 크기를 통일한다.
- 피벗: 캐릭터·몬스터는 발 아래 가운데(Bottom Center), 이펙트·아이콘은 가운데(Center).
- 크기를 바꿀 때는 Nearest Neighbor로 정수배만 쓴다. 0.5배, 1.5배처럼 정수가 아닌 배율로 줄이거나 늘리지 않는다.
- AI 생성 이미지의 픽셀 격자와 팔레트를 확인한다. 크기나 색을 바꾸어야 한다면 원본을 보존하고 결과를 비교해 사람이 결정한다. 비정수 축소는 픽셀 형태를 망가뜨릴 수 있다.
- 원본(큰 크기, 작업 파일)은 게임 폴더(`Assets/`) 밖에 따로 보관하고, `Assets/`에는 게임용 크기만 넣는다.

## 그림체와 AI 제작

[제자 기준 아트 스타일](art_style.md)을 따른다. 제자 SD의 살짝 위에서 보는 3/4 시점과 기본 스프라이트를 새 에셋의 공통 시각 기준으로 쓴다. 이미 적용한 제자와 종남 일반 상대의 실제 크기는 [에셋 목록](assets.md)을 따르고, 아직 만들지 않은 에셋의 크기는 위 계획값을 기준으로 정한다.

**에셋 생성은 루프 밖에서 사람과 함께 한다.** 사람의 참고 이미지 → 일러스트 시안 → PixelLab 기본 스프라이트 → 사람의 확정 → PixelLab 애니메이션 → 사람의 확정 순서와 보관 방법은 스타일 문서를 따른다. 기존 제자 기준 이미지가 있으므로 새 제자 기준 프레임을 먼저 만들 필요는 없다.

## 가져오기 설정

| 항목 | 값 |
| --- | --- |
| Texture Type | Sprite (2D and UI) |
| Pixels Per Unit | 32 |
| Filter Mode | Point (no filter) |
| Compression | None |
| Generate Mip Maps | 끔 |

**예외: 시작 화면과 설정·강화 UI 그림** (`Assets/Resources/Art/StartMenu/`, `Assets/Resources/Art/UI/Settings/`, `Assets/Resources/Art/UI/StatUpgrade/`, `Assets/Resources/Art/UI/OfflineReward/`). 고해상도 AI 시안을 화면에서 정수배가 아니게 줄여 보이므로, Filter Mode = Trilinear, Generate Mip Maps = 켬으로 가져온다. Point로 줄이면 제목과 버튼 글자의 선이 깨진다. 시작 화면의 최대 크기는 2048, 설정·강화 UI는 4096이다.

가져오기 설정은 `.meta` 파일에 저장된다. 루프 안의 에이전트는 `.meta`의 가져오기 설정을 직접 고치지 않는다. `Assets/Resources/Art/` 아래 그림은 `Assets/Editor/PixelArtTextureImporter.cs`(에셋 후처리기)가 가져올 때 위 값(시작 화면 그림은 위 예외)으로 맞춘다 (스프라이트 모드 Single, 9-slice 테두리는 건드리지 않음). 애니메이션 시트의 프레임 자르기와 피벗은 화면 코드가 한다.
