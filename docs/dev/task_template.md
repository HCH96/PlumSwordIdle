# 작업 문서 양식

`tasks/todo/`에 넣는 작업 문서의 양식이다. `plan-feature` 스킬로 사양(`docs/spec/<기능>.md`)을 정한 뒤 `make-tasks` 스킬이 이 양식으로 쪼개 넣는다.

## 규칙

- **파일 이름**: `번호_짧은이름.md` (예: `001_currency.md`). 루프는 번호가 작은 것부터 처리한다.
- **선행 작업**: 먼저 끝나야 하는 작업 문서의 파일 이름을 `.md` 없이 한 줄에 하나씩 적는다 (예: `- 001_currency`). 없으면 `없음`.
  - **문서 이름만 적는다.** 설명, 괄호, 쉼표, 마침표, `.md`를 붙이지 않는다. 스크립트가 이 칸의 글자를 그대로 이름으로 읽는다.
  - 루프 스크립트가 이 칸을 직접 읽는다. 선행 작업이 아직 끝나지 않았으면 문서를 `tasks/wait/`로 옮기고, 끝나면 다시 `tasks/todo/`로 올린다.
  - 완료 판정: `tasks/done/`에 있거나 `docs/history/`에 기록이 있으면 완료다.
- **묶음**: 한 루프에서 함께 처리할 작업 묶음 이름 (예: `재화`). 루프 하나는 묶음 하나만 처리하고, 루프 브랜치를 main에 합친 뒤 다음 묶음을 처리한다. 비워 두면 `기본` 묶음이 된다. 띄어쓰기와 괄호가 없는 한 단어로 적고, 같은 묶음의 문서는 글자 하나까지 똑같이 적는다.
- **완료 조건**: 화면 작업은 항목 앞에 `[테스트]`, `[컴파일]`, `[플레이 모드]`, `[사람 확인]` 표시를 붙여 무엇으로 판정하는지 적는다. 표시가 없으면 에딧 모드 테스트로 판정하는 조건이다. `[사람 확인]`은 루프가 판정하지 않고 리뷰(`review-loop`) 때 사람이 본다.
- 칸 제목(`## 목표` 등)은 바꾸지 않는다. 스크립트는 `## 선행 작업`, `## 묶음` 제목으로 칸을 찾는다.

## 양식

```markdown
# 001_currency — 재화 지급·소비 기능

## 목표
이 작업으로 무엇을 만드는지 한두 줄

## 묶음
재화

## 선행 작업
없음

## 참고 문서
- docs/index.md
- docs/dev/architecture.md
- docs/spec/currency.md

## 요구사항
- 구체적인 동작

## 완료 조건
- 기계가 참/거짓을 판정할 수 있는 테스트 기준 (가장 중요)

## 하지 말 것
- 건드리면 안 되는 범위
```
