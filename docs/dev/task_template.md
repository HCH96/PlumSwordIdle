# 작업 문서 양식

`tasks/todo/`에 넣는 작업 문서의 양식이다. `plan-feature` 스킬로 사양(`docs/spec/<기능>.md`)을 정한 뒤 `make-tasks` 스킬이 이 양식으로 쪼개 넣는다.

## 규칙

- **파일 이름**: `번호_짧은이름.md` (예: `001_currency.md`). 루프는 번호가 작은 것부터 처리한다.
- **선행 작업**: 먼저 끝나야 하는 작업 문서의 파일 이름을 `.md` 없이 한 줄에 하나씩 적는다 (예: `- 001_currency`). 없으면 `없음`.
  - **문서 이름만 적는다.** 설명, 괄호, 쉼표, 마침표, `.md`를 붙이지 않는다. 스크립트가 이 칸의 글자를 그대로 이름으로 읽는다.
  - 루프 스크립트가 이 칸을 직접 읽는다. 선행 작업이 아직 끝나지 않았으면 문서를 `tasks/wait/`로 옮기고, 끝나면 다시 `tasks/todo/`로 올린다.
  - 완료 판정: 통합 브랜치의 `docs/history/`에 기록이 있으면 완료다 (루프가 검증을 통과해 합쳐져야 기록이 생긴다).
- **묶음**: 한 루프에서 함께 처리할 작업 묶음 이름 (예: `재화`). 루프 하나는 묶음 하나만 처리하고, 검증을 통과하면 통합 브랜치에 합친 뒤 곧바로 다음 묶음을 처리한다. 묶음 하나가 병합 커밋 하나, 증거 보고서 하나가 되므로 **함께 확인하고 함께 되돌릴 단위**로 나눈다. 비워 두면 `기본` 묶음이 된다. 띄어쓰기와 괄호가 없는 한 단어로 적고, 같은 묶음의 문서는 글자 하나까지 똑같이 적는다.
- **참고 문서**: 프로젝트 루트 기준의 `docs/` 아래 경로만 한 줄에 하나씩 적는다 (예: `- docs/spec/currency.md`). 코드 파일이나 `docs/` 밖 경로는 작업 검사(`make-tasks`)에서 거부된다. 코드가 필요하면 요구사항 칸에 경로를 적는다. 적은 문서는 main 또는 통합 브랜치에 커밋되어 있어야 한다 (미커밋 문서는 루프가 읽지 못한다).
- **완료 조건**: 화면 작업은 항목 앞에 `[테스트]`, `[컴파일]`, `[플레이 모드]`, `[사람 확인]` 표시를 붙여 무엇으로 판정하는지 적는다. 표시가 없으면 에딧 모드 테스트로 판정하는 조건이다. `[사람 확인]`은 루프가 판정하지 않고, 루프 증거(`docs/evidence/<루프>/report.md`)의 "사람이 볼 것"에 화면 갈무리와 함께 모인다. 사람이 main 에 올리기 전에 본다.
- **관문 예외** (선택): 작업이 어셈블리 정의나 씬처럼 평소에는 바꾸면 안 되는 것을 바꿔야 할 때만 `## 관문 예외` 칸을 `## 하지 말 것` 앞에 두고, 한 줄에 하나씩 이름을 적는다. `asmdef`(어셈블리 정의), `scene`(`.unity`·`.prefab`·`.asset`), `settings`(`ProjectSettings/`·`Packages/`). 이 칸이 없으면 그런 변경은 관문에서 떨어져 합쳐지지 않는다 ([loop.md](loop.md) "검증"). 루프 자체(`tools/loop/`, `CLAUDE.md` 등)는 예외를 줄 수 없다.
- 칸 제목(`## 목표` 등)은 바꾸지 않는다. 스크립트는 `## 선행 작업`, `## 묶음` 제목으로 칸을 찾는다.

## 양식

```markdown
# 001_currency — 재화 지급·소비 기능

## 목표
이 작업으로 무엇을 만드는지 한두 줄

## 묶음
재화

## 선행 작업
없음

## 참고 문서
- docs/index.md
- docs/dev/architecture.md
- docs/spec/currency.md

## 요구사항
- 구체적인 동작

## 완료 조건
- 기계가 참/거짓을 판정할 수 있는 테스트 기준 (가장 중요)

## 하지 말 것
- 건드리면 안 되는 범위
```
